# rollcall

以 Google 試算表為名單與紀錄的活動報到系統：掃描在本機即時判定，Apps Script 批次寫入並同步各入口。

用語見 [CONTEXT.md](CONTEXT.md)，設計決策見 [docs/adr/](docs/adr/)。

## 給主辦方

1. 複製[範本試算表](https://docs.google.com/spreadsheets/d/1a5Gwgj0JRs5ndHNk8BjRN9rrhOAJBrciu6u_tmrd-pw/edit)（「檔案 → 建立副本」）。名單放在「學員名單」分頁，第 1 列是標題，必須有「學員代號」（票券模式可以省略）；有「手機」欄就能用手機報到。名單想放在別的分頁（例如表單回應），在「報到 → 設定」的「名單分頁」選它。
2. 「擴充功能 → Apps Script → 部署 → 新增部署作業」，類型選網頁應用程式，執行身分「我」，存取權「所有人」。
3. 用瀏覽器開一次部署出來的網址，依指示授權，看到「已完成初始化」。
4. 回到試算表，選單「報到 → 設定」填報到成功訊息與場次，「報到 → 工作人員連結」把連結或 QR code 交給入口工作人員。

掃描頁可以用相機掃 QR code、Code 128、Code 39（學員證上的條碼內容就是學員代號），也可以接 USB 條碼槍或直接輸入學員代號或手機。

報到分頁的前 5 欄由程式寫入；之後的標題列填學員名單的欄位名稱，報到時會從名單查出填入。學員名單的「{場次} 報到時間」欄由程式維護。

活動前測試過掃描的話，用選單「報到 → 清除報到紀錄」清掉該場次的報到紀錄與學員名單上的報到時間。只能在沒有入口正在報到時清除，清除後所有開著的掃描頁都要重新整理，否則仍會把清掉的學員當成已報到。手動刪報到分頁的列不會取消報到，也會讓之後的紀錄前面留下空白列。

### 票券模式

要用簽章的 QR 票券（名單上的票與不記名的實體票）入場時，在「報到 → 設定」把模式改成票券模式。試算表會多出「票種規則」分頁，學員名單多出「序號」「票券」「票券 QR」三欄，選單多出「票券」。

1. 「票券 → 產生金鑰對」。之後再產生一次，先前簽發的票券全部失效。
2. 在學員名單的「序號」欄自己填序號，或選取那幾格用「票券 → 填入流水號」。序號只能用英數字、`-`、`_`，最長 32 字。「學員代號」可以空白或整欄刪掉，報到紀錄會改記序號。
3. 選取要發票的列，「票券 → 簽發選取的列」，寫入「票券」文字與 QR，並設好列高。改了序號、換了金鑰或 QR 圖不見了，重跑一次就會更新。
4. 「票券 → 產生實體票」在側邊欄填前綴與張數。輸出選「列印頁與 CSV」時，在瀏覽器開列印頁（每格一張 QR 與序號，可另存 PDF），或下載「序號,票券」的 CSV 給印刷廠，試算表不留單張紀錄，幾千張也只要幾秒；關掉側邊欄前要先印或下載。選「寫入新分頁」時每張 QR 約 0.7 秒，印完刪掉分頁。兩種都會分段進行並顯示進度，中斷了可以從中斷處繼續；試算表只記前綴與下一號。
5. 在「票種規則」由上往下填比對、動作、訊息，用「票券 → 測試規則」輸入序號確認會套到哪一條。

| 比對 | 動作 | 訊息 |
|---|---|---|
| `P03-` | 拒絕 | 此批票券已作廢 |
| `VIP` | 需在名單 | 貴賓 {{姓名}}，歡迎 |
| `P` | 放行 | 實體票 {{序號}}，歡迎入場 |

比對是從序號開頭起算的 regex，區分大小寫；要比對到結尾就加 `$`，例如作廢單張票 `P03-00042$`。沒有任何一條符合就拒絕。「需在名單」的票，名單上找不到序號就顯示已作廢；刪掉那一列或清掉序號就能作廢一張電子票。規則寫錯時，已開著的掃描頁沿用先前的規則並顯示警告。

前綴結尾不能是數字（`P03-` 可以，`P03` 不行），一個前綴只能用在名單或實體票其中一種，這樣序號不會撞號。

票券模式的掃描頁只認 QR 票券：相機不掃一維條碼，也不能輸入學員代號或手機；輸入框留給 USB 條碼槍。掃描頁右上角可以改入口名稱，重複入場時會顯示「x 分鐘前已於入口「東門」入場」。

### 試算表裡的其他公式

每次同步都會先讀學員名單；前一次寫入引發的重算還沒算完，這次讀取就要等，所以重的公式會拉長同步時間。報到結果在掃描頁就判定好，不受影響；變慢的是其他入口看到這筆報到的時間，以及「未送出 N 筆」清掉的時間。同步超過 10 秒只會顯示「同步延遲，照常報到」，不會禁止報到。

會拖慢同步的公式有兩種：

- 引用報到分頁或學員名單「報到時間」欄的公式，例如 `COUNTIF(報到!D:D, …)`、`QUERY(學員名單!…)`：每次同步寫入後重算，範圍越大、函式越重越慢，每一列各查一次整張表的寫法最慢。
- volatile 函式 `NOW`、`TODAY`、`RAND`、`INDIRECT`、`OFFSET`：試算表任何地方被編輯就重算，不管引用什麼。

統計、儀表板放在另一份試算表，用 `IMPORTRANGE` 讀資料，重算就發生在那一份。一定要放在同一份的話，不用 volatile 函式，範圍寫成有界的（`D2:D2000`，不寫 `D:D`），也不要每一列各查一次整張表。

## 結構

| 目錄 | 內容 |
|---|---|
| `core/` | 純 TypeScript 領域邏輯：模板、名單快取、同步、請求驗證。不依賴 Apps Script 或 DOM，用 `node --test` 測 |
| `gas/app/` | 綁定範本試算表的 Apps Script：Web App API、選單、側邊欄 |
| `web/` | 掃描頁，GitHub Pages 提供（`main` 推送後由 `.github/workflows/pages.yml` 部署） |
| `scripts/build.ts` | esbuild 打包，輸出到 `dist/` |

Apps Script 只認得頂層函式，所以建置時會替 `gas/app/main.ts` export 的每個函式，在檔尾補一個同名的頂層函式。

## 指令

```bash
npm test
```

```bash
npm run typecheck
```

```bash
npm run build
```

推送 Apps Script 用 `npx clasp -P <專案檔> push`，專案檔的 `rootDir` 指向 `dist/gas/app`：

| 專案檔 | 對象 | 建置 |
|---|---|---|
| `.clasp.template.json` | 範本試算表 | `npm run build` |
| `.clasp.test.json` | 測試試算表 `rollcall-test` | `npm run build -- --dev`，多出端到端測試用的 `devSeed`／`devDump` |

兩個專案檔都不進版控。
