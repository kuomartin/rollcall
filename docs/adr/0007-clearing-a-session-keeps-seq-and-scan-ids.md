# 清除場次時不重設 seq、不清已見過的 scanId，入口要重新整理

主辦方可以在選單清除一個場次的報到紀錄，用於活動前清掉測試掃描。清除會在 script lock 內清空該場次報到分頁第 2 列以後、學員名單的「{場次} 報到時間」欄，把該場次的列計數器設成 2，並從 CacheService 的近期紀錄濾掉該場次。

`seq` 不歸零：它是所有場次共用的流水號，入口拿它當 cursor，歸零後 `since(cursor)` 會一直回空，直到新的 seq 追過入口手上的值。已見過的 scanId 不清：清除後才送到的測試掃描會被當成重送而丟掉，正是想要的結果。

掃描頁不會自動得知清除：它把記憶體裡的近期紀錄併進已報到索引，就算重抓名單也會把清掉的學員算回已報到。所以清除後要重新整理所有掃描頁，對話框與 README 都這樣要求。

## Consequences

- 清除時已預留列號、還沒寫入的批次，或入口尚未送出的掃描，清除後仍會寫進該場次。所以只能在沒有入口正在報到時清除。
- 清除無法復原；對話框要求輸入場次名稱才能執行。
