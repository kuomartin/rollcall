# 同步時 lock 只保護記帳，寫試算表在放開 lock 之後

每次同步在 script lock 內只做記帳：依 scanId 去重、分配 seq、替每個報到分頁預留不重疊的列範圍、更新 CacheService 裡的近期紀錄與已見過的 scanId；放開 lock 後才把列寫進預留的範圍、更新學員名單的報到時間。實測 lock 內讀寫試算表一次要持有約 1.3 秒，8 個入口同時同步就等到逾時；改成只記帳後，持有時間 p50 約 0.3 秒，8 個入口 × 4 批無錯誤、無重複、無缺漏。

## Consequences

- 已見過的 scanId 存在 CacheService：快取被清掉後重送的掃描可能多寫一列。報到本來就允許重複，所以接受。
- 預留的列範圍若不是空的（有人手動插入或刪除了列），那一批改在 lock 內接在最後一列之後寫，並校正計數器。
- 同步回應的 `entries` 只涵蓋最近 300 筆；剛開頁的入口拿到的就是這 300 筆。
